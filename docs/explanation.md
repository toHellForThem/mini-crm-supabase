# Как устроена система и как защищены данные

## Что это

Небольшая CRM для стройки. В ней есть **объекты** (стройки) и **задачи** внутри объектов. Два типа сотрудников:

- **Постановщик** — ставит задачи, назначает исполнителей, принимает результат или отправляет на доработку.
- **Исполнитель** — видит только свои задачи и объекты, где эти задачи есть. Он может взять задачу в работу и отправить на проверку.

У задачи есть жизненный цикл: *Новая → В работе → На проверке → Принята* или *На доработке → В работе*. Любое изменение статуса сохраняется в истории: кто, когда, из какого статуса в какой и с каким комментарием.

## Как защищены данные

Система построена так, что правила проверяются **на сервере базы данных**, а не только на экране. Даже если злоумышленник отправит запрос напрямую в базу, минуя сайт, правила всё равно сработают.

1. **Каждый видит только своё.** В базе включён режим «построчной защиты» (Row Level Security). Для исполнителя база физически не отдаёт чужие задачи и объекты. Это не «скрыто в интерфейсе» — данные просто не возвращаются.
2. **Нельзя поменять статус в обход правил.** Смена статуса идёт только через специальную серверную функцию. Она проверяет: кто вы, ваша ли это задача и разрешён ли такой переход. Например, исполнитель не может принять свою же задачу, а постановщик не может вернуть на доработку без комментария. Любая попытка запрещённого перехода завершается отказом.
3. **Историю нельзя подделать.** Таблица истории доступна только на чтение через API. Записи в неё добавляет только сама база в момент смены статуса. Изменить, удалить или вписать свою запись через запрос невозможно.
4. **Новые задачи всегда начинаются с «Новой».** Даже если создать задачу сразу со статусом «Принята», база не даст этого сделать.
5. **Регистрация закрыта.** Новых пользователей создаёт только администратор в панели Supabase. Секретный ключ администратора (service_role) не используется во фронтенде и не хранится в репозитории — на сайте есть только публичный ключ, который сам по себе ничего не разрешает.

## Что не может сделать исполнитель

- Увидеть или открыть чужую задачу — база не вернёт её.
- Увидеть объект, где у него нет ни одной задачи.
- Поменять статус задачи, которая назначена не ему.
- Принять задачу или вернуть её на доработку — это только для постановщика.
- Изменить или удалить историю статусов.
- Создавать, редактировать или удалять задачи и объекты.
- Зарегистрироваться самостоятельно.

## Итог

Интерфейс показывает только доступные кнопки, но безопасность держится не на нём, а на правилах базы данных. Поэтому даже прямой запрос к Supabase в обход сайта не позволит исполнителю сделать больше, чем ему разрешено.
